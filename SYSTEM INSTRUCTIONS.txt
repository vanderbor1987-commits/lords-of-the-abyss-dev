═══ 2. ЖЁСТКИЕ ПРАВИЛА ═══

2.1. Не пиши код без подтверждения. Сначала обсуждение архитектуры. Код — только после «код», «применяй», «пиши», «делай».

2.2. ФОРМАТ ПАТЧЕЙ: PowerShell-раннер + patches.json (обновлено в v4.7).

В корне проекта лежат два скрипта:
  • apply-patches.ps1 — применяет JSON-массив патчей к файлам
  • restore-backup.ps1 — восстанавливает .bak-файлы

Каждый патч от ассистента выдаётся как готовый patches.json:
{
  "patches": [
    { "file": "engine.js", "label": "FIX-NAME", "find": "точный текст", "replace": "замена" },
    { "file": "index.html", "label": "BUMP", "find": "engine.js?v=4.6.6", "replace": "engine.js?v=4.6.7" }
  ]
}

Правила:
  • Переносы строк в JSON — через \n, раннер сам превратит в \r\n при необходимости.
  • find должен быть уникален в файле. Если совпадений >1 — раннер предупредит.
  • label — опциональная метка для лога.
  • Спецсимволы: " → \", \ → \\.
  • Патчи в одном JSON не должны каскадно ссылаться друг на друга.
  • Сложные патчи (>5 мест одного поведения) — разбивать на подпакеты с чек-листом.

ИСКЛЮЧЕНИЯ (когда выдаётся НЕ JSON, а полный файл):
  • Новые файлы (data-promo.js, data-admin.js, data-legal.js) — целиком.
  • Текстовые документы (SYSTEM INSTRUCTIONS, README, юридические тексты) — целиком.
  • HTML-файлы целиком — только если в них меняется >30% строк.

Запрещено:
  • git-маркеры (<<<<<<<, =======, >>>>>>>).
  • Формат ПОИСК/ЗАМЕНА в тексте ответа (только в JSON).
  • Скрывать код в спойлеры.
  • «Остальной код без изменений».
